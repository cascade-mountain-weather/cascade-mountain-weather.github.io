# Cascade Mountain Weather

Jekyll site on GitHub Pages (custom domain via `CNAME`) with weekly weekend ski forecasts for Washington Cascades areas, live weather/model tools, and a forecast-evaluation page. Built by GitHub Pages' own Jekyll pipeline on push — no GitHub Actions build/deploy step for the site itself. See `PLAN.md` for the in-progress UI/feature revamp for this season.

Areas covered: Mt. Baker, Stevens Pass, Snoqualmie Pass, Blewett Pass, Crystal, Paradise, White Pass, Hurricane Ridge, Washington Pass.

**Migrated from hand-duplicated HTML to Jekyll in September 2026** (see git history around that date) to remove the header/nav/footer duplication across ~35 pages and replace fetch-and-probe JavaScript (scanning for post files by guessing filenames) with native Jekyll collections/Liquid. Old posts were kept as HTML content (not converted to Markdown) with front matter added; only the shared chrome moved into layouts/includes.

## Layout

- `_config.yml`: site config, defaults, `exclude:` list (Python-only folders like `scripts/`, `data/`, and non-site docs are excluded from the build — check this list before adding new top-level files, since anything not excluded gets copied into `_site` and deployed).
- `_includes/`: `head.html` (meta/SEO/GA), `header.html`, `nav.html`, `footer.html`, `pwa-scripts.html` (header.js + service worker registration + offline banner, included on every page).
- `_layouts/`: `page.html` (default full-doc layout for standalone pages), `post.html` (wraps forecast posts in the post-header/post-content/post-footer structure), `home.html` (bespoke, for `index.html` only — has the page-loader, satellite looper, and DGZ education content).
- `_posts/YYYY-MM-DD-weekend-forecast.html`: one file per forecast post, front matter + body only (no `<html>/<head>/<header>` boilerplate — that's the layout's job). Front matter fields: `title`, `description`, `keywords`, `tagline`/`summary` (used by the homepage hero for the latest post), `forecast_period` (just the date range text), optional `closing_note`. The date comes from the filename. Jekyll's `permalink` in `_config.yml` keeps the historical URL scheme `/posts/YYYY-MM-DD-weekend-forecast.html`, so old links and `../assets/...` image paths inside post bodies still work unchanged.
- `posts/TEMPLATE-post.html`: copy-paste starting point for a new post (excluded from the build via `_config.yml`, never published itself). `posts/archive.html` and `posts/post-style.css` remain in `posts/`, not `_posts/`, since they aren't dated posts.
- Top-level pages (`about.html`, `model-tools.html`, `evaluation.html`, `sitemap-page.html`, `tools/*.html`, `index.html`) are Jekyll pages: front matter (`layout`, `title`, `description`, etc.) + body content only.
- `assets/images/YYYYMMDD_fx/`: figures for each week's post (folder date matches the post date). `assets/images/satellite/`, `gfs_dgz_F24.png`: auto-generated by workflows — do not hand-edit.
- `tools/model-tools-current-weather.html`: **not** a Jekyll page — it has no front matter and is fully regenerated by `scripts/collect_weather_data.py` from `scripts/models-tools-current-weather.tpl.html` via the hourly `synoptic.yml` workflow. Edit the `.tpl.html`, never this output file.
- `data/`, `scripts/`, `cascade_weather_app/`: excluded from the Jekyll build entirely (Python/Flutter inputs, not served). `evaluation.html`'s stats are baked in by `scripts/populate_evaluation_html.py`, which does regex-based in-place edits keyed to specific class names (`stat-number`, `seasonal-card[data-region=...]`, etc.) — when touching `evaluation.html`'s content, keep those exact classes/structure intact or the script's replacements will silently stop matching.
- PWA: `manifest.json`, `service-worker.js`. Bump the cache version in `service-worker.js` if cached assets change.
- `sitemap.xml` is now generated at build time by the `jekyll-sitemap` plugin — it is **not** a source file and must not be hand-edited or committed; `scripts/generate_sitemap.py` and its workflow were removed.

## How things connect

- The homepage "Latest Forecast" hero, "Recent Forecasts" list, and `posts/archive.html` are all driven by `site.posts` (Liquid), sorted newest-first automatically by Jekyll. There is no `latest-post-summary.html` anymore and no client-side fetch/probe JS for posts — publishing a new post file is the only step needed to update all three.
- `_includes/head.html` appends " | Cascade Mountain Weather" to post `<title>`/og:title automatically (posts' front matter `title` is just the plain heading text, matching what shows in the post header/archive/recent-posts list).

## Local preview

Ruby/Jekyll are installed locally. From the repo root: `jekyll build` (or `bundle exec jekyll build` using the checked-in `Gemfile`) to build into `_site/` (gitignored), or `jekyll serve` to preview at `http://localhost:4000` with live reload. Always do this before pushing a structural/layout change — GitHub Pages' build environment is otherwise the first place a Liquid error would surface.

## Git and workflow

- Remotes: `origin` = cascade-mountain-weather.github.io, `upstream` = Cascski-Alpine-Insights. Default branch is `main`. Danny works on branch `danny` (a `clinton` branch also exists) and merges via PR into `main`.
- Bots push constantly to `main` ("Update weather data [skip ci]", "Update GFS plot", "Update satellite looper assets"). Expect `git pull --rebase` before pushing, and never hand-resolve conflicts in the auto-generated files by editing them, just take the bot's version.
- Commit messages are short and lowercase-ish (e.g. "posting this week's forecast", "update latest post").

## Conventions and gotchas

- Forecast posts are written in an informal, humorous voice with an emoji-laden tagline. When editing post prose, preserve Danny's voice and never invent forecast numbers, model output, or observations. Ask for them.
- The README, QUICK-GUIDE, and EVALUATION-GUIDE predate the Jekyll migration and describe the old structure (raw HTML posts, manual archive/homepage edits, `Dawg-Winter-Weather-Blog` repo name). Trust this file and the code over them until they're rewritten.
- Image files in `assets/images/*_fx/` are large (up to several MB). Don't re-encode or delete them without asking.
- Paths contain spaces (`OneDrive - UW`), so quote them in shell commands. Shell is PowerShell on Windows, with Git Bash also available; Bash invocations in this OneDrive-synced folder can take ~90s to start (first-run/AV scan), not a hang — give commands time before assuming they're stuck.

## Skills in this repo

- `/new-forecast-post`: scaffold a weekly post as a new `_posts/` file from the template.
- `/run-evaluation`: run the weekly forecast evaluation and refresh `evaluation.html`.
- `/site-check`: sanity-check front matter, leftover template markers, and image references before pushing; optionally run a Jekyll build to catch Liquid errors.
